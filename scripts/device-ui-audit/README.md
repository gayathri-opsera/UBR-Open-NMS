# Device web UI ↔ Node View audit

Proves that a Custom UI Builder v2 screen shows the same values as the device's own web UI.

1. `crawl.mjs`      — headless Chrome reads every page/tab of the device web UI (GET only) → `device_ui.json`
2. `snmpget_all.py` — reads candidate OIDs through the NMS (`POST /api/node-view/:id/snmp-get`, admin only, GET only) → `snmp_values.json`
3. `spec.py`        — the mapping: each web-UI field → MIB object / row, value labels, templates; builds the screen's sections
4. `apply.py`       — saves the sections on the screen and publishes it (`--no-backup` to skip the backup copy)
5. `render_nv.mjs`  — renders the device's Node View, walks every menu item and tab → `nv_render.json`
6. `compare.py`     — compares each rendered value with the web UI's value (live values: format only)

Needs `login.json` (the NMS login response). Nothing here stores a device credential.

`device_ui.json` and `web_parsed.json` (the crawl output) are generated by `crawl.mjs` and are deliberately **not committed**: they hold the
device's settings, including credentials. Run the crawl first; `spec.py` reads `web_parsed.json`.

## Editability check (every property of every field kind can be changed in the builder)
Duplicate the screen (a throwaway draft), write its id to `copy_id` and the field/section ids to `ids.json`, then:
`node edit_test.mjs` (drives the real Inspector controls, 47 edits) → `python3 verify_edits.py` (checks each edit in the stored screen).
Never run it on the live screen.
