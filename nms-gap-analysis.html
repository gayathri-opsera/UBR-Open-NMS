⭐ Why This Reference Architecture Matters

🌐

Multi-Vendor Heterogeneity

Manages Cisco, Juniper, Huawei, Arista, Nokia, cloud-managed (Meraki, Aruba) and OT/Industrial devices through a single unified model — no per-vendor core changes.

🔄

Protocol Fallback Chain

Automatically tries Agent → NETCONF → SNMP → CLI → ICMP per operation. If one protocol fails, the next is tried silently — zero manual intervention needed.

🛡️

Secure Credential Handling

Vault-based credential indirection — secrets never stored inline, never in logs, rotatable without device config changes. Meets SOC2 / PCI-DSS requirements.

⚡

Autonomous Operations

Pre/post validation hooks, automated rollback on failure, async job engine for firmware upgrades, config pushes — no operator babysitting required.

🧩

Extensible Plugin Architecture

Hot-loadable vendor driver plugins. Adding a new vendor requires only a new plugin, zero changes to core services. Future-proof for any device type.

📈

Carrier-Grade Scale

Per-device rate limiting protects legacy/OT devices from management plane saturation. Event-driven Kafka backbone enables horizontal scale across all services.

🔬

Root Cause Analysis

Topology dependency graph enables true RCA — when a parent switch fails, child alarm storms are suppressed and operators see one root cause alert, not hundreds.

📋

Full FCAPS Coverage

Fault, Configuration, Accounting, Performance, Security — all five management domains addressed. From SNMP trap ingestion to firmware upgrades to compliance auditing.

Moderate Coverage — Strong Upper Layers, Weak Foundation

UBR NMS excels at the presentation and event-processing layers (frontend, API gateway, alarms, notifications, KPI collection) — areas visible to operators. The critical gaps are in the foundational layers: Device Abstraction, Southbound Adapters, Operations Engine, and Credential Management. These gaps limit the system to a single-vendor (Airtel BTS/CPE/IDU) use case and prevent it from being a true multi-vendor NMS.

❌ Not Covered 20 Critical Gaps

🔴 Critical

Capability Registry

Protocol priority chain per device type (Agent→NETCONF→SNMP→CLI). Without it, services hardcode protocol assumptions and protocol fallback is impossible.

🔴 Critical

Driver / Plugin Manager

Hot-loadable vendor plugins implementing a common Driver interface. Adding a new vendor (Juniper, Huawei) requires core code changes today — a plugin would be sufficient.

🔴 Critical

Protocol Fallback Chain

Automatic fallback Agent→NETCONF→SNMP→CLI when a protocol is unavailable. Currently the system fails completely if one protocol fails.

🔴 Critical

Secret Store (HashiCorp Vault)

Credentials stored in env vars/MongoDB — never inline. Vault provides lease-based rotation, full audit trail, and SOC2/PCI-DSS compliance. Currently a critical security gap.

🟠 High

Async Job Queue (Temporal)

No async tracking for device operations. Long-running firmware upgrades / config pushes block API threads today. Temporal provides durable execution with retry and compensation.

🟠 High

Git-backed Config Repository

Per-device config versioning with diff, blame, and history. No config compare (running vs startup vs golden template). Required for compliance and rollback.

🟠 High

Root Cause Analysis (RCA)

Topology dependency graph-based RCA. Without it, when a parent switch fails, operators receive hundreds of child device alarms instead of one root cause alert.

🟠 High

NMS Agent (gRPC/TLS)

Lightweight daemon for server, container, SD-WAN edge, and NAT-behind device management. Push-mode for NAT traversal. First-class for environments where SNMP is insufficient.

🟠 High

Full NETCONF/YANG Adapter

RFC 6241 compliant with OpenConfig models and candidate datastore transactional commit/rollback semantics. Currently only basic ncclient usage — no YANG model validation.

🟠 High

Compliance Checker

Policy rule set enforcement on device configs. Without it, no automated compliance auditing (SOX, PCI-DSS, CIS benchmarks). Manual review required for every device.

🟡 Medium

Per-Device Rate Limiting (DAL)

Capability Registry-based per-device concurrency limits. Legacy and OT devices with weak management CPUs can be polled into instability without this protection.

🟡 Medium

Connection Pool

Managed SNMP/SSH connection pool. New connection per operation today — high overhead and slow for high-frequency polling or bulk operations across many devices.

🟡 Medium

Flap Suppression & Dampening

Alarm storm prevention for bouncing links. Without dampening, a flapping interface generates thousands of alarm/clear events per hour, flooding operator consoles.

🟡 Medium

GraphQL / gRPC Northbound APIs

Only REST available today. No streaming API for northbound consumers. OSS/BSS integration requires polling REST — inefficient for high-frequency alarm correlation.

🟡 Medium

Webhook Dispatcher

No generic webhook for event-driven integrations (ServiceNow, Jira, PagerDuty, Slack). Currently hardcoded forwarders (mycom, netcool) only.

🟡 Medium

Firmware / OS Upgrade Pipeline

No lifecycle management for device firmware. Requires manual upgrade procedures. No pre-check (disk space, model compatibility), no post-verify, no rollback on failure.

🟡 Medium

MIB Compiler

Manual OID mapping in code. No dynamic MIB loading or vendor MIB compilation. Every new device metric requires code changes instead of uploading a MIB file.

🟡 Medium

REST/HTTP Device Adapter

No generic REST client for cloud-managed devices (Cisco Meraki, Aruba Central, SD-WAN controllers). Cannot manage any device with a management REST API.

🟢 Low

PostgreSQL for Inventory

MongoDB used instead. Loses relational joins, foreign keys, and SQL aggregations for inventory queries. JSONB flexibility traded for query expressiveness.

🟢 Low

VictoriaMetrics / InfluxDB

ScyllaDB used for KPI time-series (7-day TTL). Loses Prometheus PromQL compatibility and remote_write integration. VictoriaMetrics has 10x better ingest performance.

🏛️ 8 Architectural Principles — Implementation Status

Principle 01

Protocol Fallback Chain

❌ Not Implemented

DAL should try Agent→NETCONF→SNMP→CLI automatically. Currently hardcoded per service — no fallback when a protocol fails.

Principle 02

Capability-Based Operations

❌ Not Implemented

Operations should surface only for devices that support them. No Capability Registry exists — all operations are available to all devices regardless of support.

Principle 03

Driver Plugin Architecture

❌ Not Implemented

No hot-loadable vendor plugins. Adding Juniper requires core code changes. config-push-worker handles all protocols in one monolithic service.

Principle 04

Event-Driven Core

✅ Fully Implemented

All inter-service communication flows via Kafka. 8 topics, durable event replay, independently deployable services. Matches the reference principle exactly.

Principle 05

Async Operation Engine

🟡 Partial

Kafka provides async event processing. No dedicated job queue (Temporal/Celery) for device operation tracking, retry logic, or status polling.

Principle 06

Credential Indirection (Vault)

❌ Not Implemented

Credentials stored in env vars and MongoDB — not Vault. No lease-based rotation, no dynamic secrets, no credential audit trail.

Principle 07

Pre / Post Validation Hooks

❌ Not Implemented

No mandatory pre-check snapshot or post-check verify for state-changing operations. No automated rollback on failed post-validation.

Principle 08

Per-Device Rate Limiting

🟡 Partial

API-level rate limiting exists (100 req/min per user). No per-device concurrency limits in the DAL to protect legacy/OT devices from polling instability.
